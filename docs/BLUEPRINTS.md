VisionX follows the shared blueprints in https://github.com/gadominas/app-blueprints.
The script's `BLUEPRINTS` block is the source of truth; this table mirrors it and adds deviations.

| Blueprint | Version | Since app version | Deviations |

| [settings](https://github.com/gadominas/app-blueprints/blob/settings-v1.0.0/blueprints/settings.md) | 1.0.0 | 1.9.0 | Session setup (presets, instructions, Analyze with, interval, camera, image detail, photo size, zoom, shortcut names) stays on the main screen as remembered picks in `vision-session.json`; "Sans serif" keeps the rounded headline font; the page script is a `String.raw` template, so the sheet code builds its markup with plain strings; sheet CSS is scoped under `#cfgsheet` because the app already uses `.switch`, `.chip` and `.sheet`; the old colour names are kept as aliases of the shared tokens, plus the app colour `--rec` per palette; AI settings is disabled in the sheet while a session runs; Tiny keeps the latest photo large and puts older photos on one line each |

| [ai-invitation](https://github.com/gadominas/app-blueprints/blob/ai-invitation-v1.2.1/blueprints/ai-invitation.md) | 1.2.1 | 1.20.0 | **The key decides, except for Apple Intelligence:** VisionX also analyzes photos, refines instructions and checks triggers with Apple Intelligence through Shortcuts, which needs no key. `aiInviteDue` therefore also returns false while Apple Intelligence is in use: picked under **Analyze with** and already worked (a saved session with photos analyzed on it, `appleIntelligenceInUse()`). "Analyze with" alone can't decide, because without a key it always shows Apple Intelligence, set up or not; a new user with neither a key nor a working shortcut is still invited. `inviteIfDue` checks VisionX's `ctx.update` (its `pendingUpdate`) and reaches the page with `ev()`; the page reports through `nativeCall` (its `send`); `aiInvite*` save with `saveSettings()` (its `saveAll`). `aiInviteKeyRemoved()` runs in `airm` after VisionX switches to the other provider's key, so it only fires when no key is left. `window.canInvite` holds the card back while a capture session starts, runs or is paused; the busy check also waits for the session-ended card (`#modal`) and the instructions editor (`#editor`). VisionX's AI sheet loads its state as it opens and its buttons use `data-aiact`, so the **Add key** nudge targets `#aisheet .aicard.active [data-aiact="aikey"]` (the provider in use; the first button only if no card is marked) once that state has arrived (through `window.__aiChanged`). `z-index: 47` is kept; in VisionX's own layer order it sits above the update sheet (30) and below Settings (50), and is never shown with either |

## Recipes

Coding rules every app follows (https://github.com/gadominas/app-blueprints/tree/main/recipes). They describe how the code is written, not a feature, so they aren't listed in the script's `BLUEPRINTS` block or in Built with.

| Recipe | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [safe-startup](https://github.com/gadominas/app-blueprints/blob/safe-startup-v1.1.0/recipes/safe-startup.md) | 1.1.0 | 1.20.0 | Only `settings.json` is in iCloud; the data files are on this iPhone (`vision-session.json`, the `VisionX-sessions` folder, `visionx-usage.json`), so `loadData()` reads them with `readStore()`, `sesIndex()` and `loadLocal()` (for `visionx-usage.json`), and the write guard lives in `writeStore()` and `aiWrite("usage")` rather than in `write()`. `loadLocal()` applies `load()`'s rules to those local files without the iCloud wait: unreadable goes to `loadIssues` (not saved over), damaged is copied aside by the recipe's `keepBroken()` (`vision-session.broken-<time>.json`, `visionx-usage.broken-<time>.json`) and goes to `loadRepaired` (saved normally). `visionx-ai-settings.json` counts as settings and stays read before every branch. `loadData()` reads the sessions index read-only (the widget never deletes); the app trims it to **Sessions kept** in `bootApp`, which also runs the 1.7.x key migration. The big list handed over in pieces is `sessions` (with thumbnails), 3 at a time. VisionX's views are in the markup rather than drawn by a first render, so they stay hidden (`body:not(.booted)`) until `__boot` has run `clientApp`, which then removes the placeholder. The real page keeps its `https://localhost/` base URL (the camera needs a secure origin). No refresh of its own at 0.7 s; the update check (3.5 s) and the widget's logo tile (6 s) are deferred. On close, `saveOnClose()` reads the presets from the page as before (only after `__boot`). `evaluateJavaScript` calls end in `'ok'`, as elsewhere in VisionX. Trigger and Apple Intelligence shortcuts run from the open window as before; no branch builds a WebView it didn't before |
